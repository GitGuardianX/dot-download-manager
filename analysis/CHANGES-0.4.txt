DOT 0.4: AN INSTALLED WINDOWS PROGRAM

Goal: install and run like normal Windows software (IDM-style): a setup wizard, a program
folder of exe/DLL files, Start Menu entry, tray icon, uninstaller, bundled video tools.

Packaging
  - PyInstaller one-folder build: DOT.exe + _internal\ (python314.dll, tcl86t.dll, tk86t.dll,
    libssl/libcrypto, VCRUNTIME140, .pyd modules). Nothing is unpacked to %TEMP% at start.
    DOT.exe carries Windows version details.
  - Inno Setup installer dist\DOT-Setup-0.4.0.exe (103 MB): per-user by default (no admin
    prompt) or all users; Start Menu, optional desktop shortcut, optional start in the tray
    at sign-in; closes a running DOT before upgrading/uninstalling (posts its tray window's
    exit message); clean upgrades; uninstaller removes everything and asks about user data.
  - Bundled yt-dlp 2026.11.23, Deno 2.9.8, FFmpeg 8.1.3 (LGPL shared): pinned in
    installer\tools.json, verified against the publishers' SHA-256 and locked in
    installer\tools.lock.json by tools\fetch_tools.py. License notices in licenses\.

App
  - dotdm\paths.py: installed (library %LOCALAPPDATA%\DOT, Windows Downloads folder),
    portable (portable.txt beside DOT.exe), source modes; tool lookup: user tools folder
    (updates) -> bundled -> PATH.
  - dotdm\tray.py: tray icon through ctypes (no new dependency): Open / Pause all / Start all /
    Exit, notification balloon, re-added after an Explorer restart.
  - Closing the window keeps DOT in the tray (setting); a second launch shows the running DOT;
    "DOT.exe --quit" exits it gracefully; --minimized starts in the tray.
  - "Connect your browser" guide (first run and Settings): opens the browser's extensions
    page, shows the folder to load, turns green when the extension checks in.
  - Settings: keep running in the tray, Connect your browser, Update yt-dlp.
  - The extension reports its version; DOT asks for a Reload when the browser runs an older one.

Validation
  - 89 unit tests (new: paths, tray round-trip with a private window class, close-to-tray and
    tray menu, bundled-tool preference, yt-dlp update, installer/app consistency).
  - Bundled tools read a YouTube video through DOT's code with no challenge warning.
  - tools\smoke_installer.py: silent per-user install to a temp folder (7.7 s), files, Apps
    list and Start Menu entries, a verified download by the installed DOT.exe, bundled tool
    versions, tray icon, second-launch hand-over, --quit, then a clean uninstall.

DOT 0.4.1: STREAMS THAT IDM COULD DOWNLOAD BUT DOT COULD NOT

Report: on a video site, DOT's menu offered master.m3u8 and index-v1-a1.m3u8 but both
failed ("Server returned 4XX Client Error, but not one of 40{0,1,3,4}"), while IDM
downloaded the same video.

Cause (measured against the real host): the stream host refuses any request whose Host
header is not the first header (HTTP 410 Gone; 412 without a referrer). FFmpeg's HTTP
client always sends Host fifth, after User-Agent, Referer, Accept, Range and Connection,
and that order cannot be changed. Python, curl, browsers and IDM send Host first. DOT's
referrer and user agent were correct.

Fixes
  - Browser streams (HLS/DASH) are downloaded by the bundled yt-dlp with the browser's
    referrer, user agent, Origin and the stream host's cookies; FFmpeg only joins the
    pieces locally. FFmpeg alone remains a fallback (no yt-dlp, or yt-dlp cannot read it).
  - Clicking a stream opens the Download Video window with an IDM-style quality list
    ("1920p · 4213 kbps · ~106 MiB", length) and the page's title as the file name.
  - The extension records which site's player requested a stream and replays it: an
    embedded player's site becomes the referrer, and an Origin header is sent for streams
    on another host. Variant playlists of one stream are one menu entry, not several.
  - yt-dlp runs inside a Windows job object (dotdm/processes.py). The bundled yt-dlp.exe is
    a launcher whose worker processes kept downloading after Pause, cancel or exit; now
    stopping ends the whole tree immediately, and Windows ends it if DOT exits.
  - Silent (video-only) streams no longer fail format selection.

Validation: 96 unit tests, including a local host with the same Host-first rule (yt-dlp
succeeds, FFmpeg is refused), and a launcher whose worker must stop on Pause (fails on
0.4.0, passes now); capped-Brave functional checks; a live read and partial download of
the reported stream (quality list, 19 MiB received, clean pause, files released).

DOT 0.4.2: DAILYMOTION SAVED THE PLAYLIST INSTEAD OF THE VIDEO

Report: on Dailymotion, both "Video stream (HLS)" choices finished as "Completed" with
331-byte files that were not videos; a third failed.

Cause: Dailymotion's stream links end in "manifest.m3u8#cell=cf3" and its CDN labels the
playlist "video/mp4". yt-dlp recognises an HLS link by its ".m3u8" ending, but the "#..."
part hid it, so yt-dlp trusted the wrong label and saved the playlist text as the video.
The failed one was a placeholder playlist the player loaded empty ("?error=").

Fixes
  - The "#..." part of a stream link (never sent to servers) is removed before yt-dlp or
    FFmpeg reads it.
  - A stream download that produces a playlist is a failure, never "Completed"; DOT then
    tries FFmpeg.
  - Menu entries name each stream ("Video stream (HLS) · h264_aac_hq"), and empty
    placeholder playlists are not offered.

Validation: a local host mimicking Dailymotion (video/mp4 label, #cell=cf3) saves a playable
MP4 (fails on 0.4.1); the reported stream downloads as H.264 848x480 + AAC, 23.6 s.

DOT 0.4.3: NO BUTTON ON REDDIT VIDEOS

Report: Reddit videos showed no "Download with DOT" button, while IDM offered every quality.

Cause: Reddit's <shreddit-player> keeps its <video> inside a shadow root. A video's
"playing" event does not leave a shadow root, and the one start-up look only sees the
page's own <video> elements, so DOT never noticed the video.

Fixes
  - The button also appears when the pointer moves onto a player whose video sits in a
    shadow root (found along the pointer event's own path; nothing is scanned). A player
    with a closed shadow root gets the button on the player element itself.
  - yt-dlp now needs a signed-in account to read Reddit posts ("Account authentication is
    required"); DOT never sends logins to yt-dlp, so its message now says to choose the
    "Video stream" option, which needs no login (as IDM uses).

Validation: capped Brave with open and closed shadow-root players behind a controls overlay:
no button while playing, button on hover, the open player's video sent to DOT.

DOT 0.4.4: CLEARING THE DOWNLOAD LIST

Request: with thousands of downloads, clearing everything (unfinished ones too) was hard: rows
had to be selected by hand, and each removal saved the whole list again.

Changes
  - Remove menu in the toolbar: selected, completed, failed or all downloads, with counts.
  - One confirmation window: what is removed, unfinished downloads stopped with their partial
    data deleted, and an unticked "Also delete the downloaded files from disk" (only each
    completed download's own file is deleted, never a folder).
  - Bulk removal in the engine (remove_many): one save however many downloads, disk clean-up
    after the list is saved, run in the background so the window stays responsive.
  - Ctrl+A selects every row in the current view; Delete opens the same confirmation.
  - The browser extension is unchanged (still 0.4.3).

Validation: 3,000 downloads removed with one save in moments; files kept unless ticked; a
running download stopped and removed; the window's Remove-all flow end to end.

DOT 0.4.5: FILE HOSTS THAT IDM DOWNLOADED BUT DOT DECLINED

Report: on real-debrid, clicking DOWNLOAD opened IDM's window; with IDM's Brave extension
off, Brave asked where to save and DOT never appeared.

Causes
  - IDM's Brave extension takes downloads before DOT's extension sees them (documented; the
    user turned it off).
  - DOT checks a browser download with a one-byte request (Range: bytes=0-0). real-debrid
    labels its reply "bytes 0-0/N" but sends the whole file, so DOT judged the server unable
    to do ranges and declined; the browser kept the file. Normal ranges work on that server.
  - The server sends no ETag or Last-Modified, so DOT also refused parallel pieces and
    resume (a paused 2.7 GB download would have restarted from zero).

Fixes
  - A mislabelled one-byte reply is re-checked with an ordinary 1 KiB range; parallel pieces
    if exact, else one connection. Never a declined download for this.
  - When a server names no version at all, the file's exact size identifies it (as in IDM):
    every piece and every resume must report the same total, and this identity is never
    sent as If-Range. Weak ETags and very recent Last-Modified dates stay single-stream.

Validation: local servers mimicking real-debrid (mislabelled probe, no version; parallel,
pause and resume inside pieces); the reported link accepted by DOT's browser check
(2.68 GiB) and downloaded with 8 connections over 32 pieces, resuming after a pause.
